# 架构说明

本实践演示：**用 GitHub Actions 可复用工作流 + Terraform（基础设施即代码）自动化容器镜像的构建与发布到华为云容器镜像服务（SWR）**，并通过 OpenID Connect（OIDC）实现免长期密钥的访问授权，降低人为操作错误、缩短镜像发布周期。

## 整体架构

```
          GitHub 仓库 push / 手动触发（workflow_dispatch）
                          │
                          ▼
        ┌─────────────────────────────────────┐
        │   GitHub Actions 可复用工作流        │
        │                                     │
        │  1. OIDC 免长期密钥认证              │
        │     （GitHub JWT → 华为云临时凭证）   │
        │  2. 安装 SWR SDK                    │
        │  3. 登录 SWR（短期登录指令）          │
        │  4. docker build + push             │
        └─────────────────────────────────────┘
                  │                │
        ┌─────────┴──────┐   ┌────▼─────────────┐
        │  OBS（Terraform │   │  SWR 容器镜像服务 │
        │  状态存储）      │   │  组织 + 仓库       │
        └────────────────┘   │  镜像保留策略      │
                             └──────────────────┘
```

> 说明：镜像仓库（SWR 组织 + 仓库 + 保留策略）由 Terraform 在工作流触发前创建；工作流负责「认证 → 登录 → 构建 → 推送」。

## 组件说明

| 组件 | 作用 |
|---|---|
| **GitHub Actions 可复用工作流** | 编排「认证 → 登录 → 构建 → 发布」全流程，支持手动触发或改为 `push` / `workflow_call` 触发 |
| **SWR 容器镜像服务** | 托管容器镜像仓库：采用「组织（命名空间）+ 仓库」两层模型，支持私有仓库与镜像保留策略 |
| **Terraform（基础设施即代码）** | 以声明式方式创建 SWR 组织、镜像仓库、保留策略与临时登录指令，保证可复现 |
| **OBS（对象存储服务）** | 存放 Terraform 状态文件（远程后端） |
| **IAM + OIDC 身份提供商** | 将 GitHub 的 OIDC 身份映射到华为云，为工作流发放短期临时凭证，避免保存长期密钥 |
| **SWR 临时登录指令** | 为 CI/CD 生成短期 `docker login` 命令，免长期密钥登录镜像仓库 |

## 关键设计要点

1. **免长期密钥**：工作流全程使用短期临时凭证（OIDC 换取的华为云临时访问密钥 + SWR 短期登录指令），不在仓库中保存任何长期密钥。
2. **声明式建仓**：镜像仓库及保留策略由 Terraform 声明式创建并在工作流触发前完成；新增仓库只需更新配置并执行一次 `terraform apply`。
3. **镜像保留策略**：通过保留最近 N 个镜像 tag 自动清理旧镜像，控制仓库内镜像版本的持续膨胀。
4. **私有仓库**：镜像仓库默认私有，仅授权身份可拉取/推送。

## 镜像仓库权限模型

SWR 采用「组织 + 仓库」两层模型，权限在组织层级管理：

- **组织公开/私有**：控制他人能否访问命名空间下的仓库。
- **仓库共享**：可将单个仓库以「仅拉取」权限共享给其他华为云账号。
- **组织成员权限**：为 IAM 用户/联邦用户授予「管理/写入/只读」组织权限。

> 与「针对单个仓库编写细粒度访问策略」不同，SWR 的读写授权以组织为粒度；如需对单个仓库做更细的授权，可结合 IAM 用户组的 SWR 角色实现。
